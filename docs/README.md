# 点单页 + 店员后台（静态版，托管在 GitHub Pages）

纯前端的静态站，跟后端共用同一套规则（`wxmenu.js` 与 `menu_spec.py` / `receipt.py` 输出逐字符一致，由 `test-wxmenu.js` 交叉验证）。

- `index.html` — **顾客点单页（站点首页）**。只收集地址、显示后端算好的金额；地址候选和报价都走 Worker，页面里没有任何密钥，也不自己算钱
- `admin.html` — **店员后台**：改店名/电话/菜单/配送费规则，保存到后端。进页面先验口令（服务端校验，不是前端摆设），顾客那边不给入口
- `order.html` — 老链接的跳转页（转到 `./`，之前发出去的 `/order.html` 不会失效）
- `wxmenu-editor.html` — 老的公众号菜单编辑器（微信底栏菜单 + 小票排版预览），跟点单页无关，留着备用
- `wxmenu.js` — 规则/渲染核心（浏览器 + node 通用）
- `test-wxmenu.js` — `node test-wxmenu.js` 跑自测
- `test-order-page-static.js` — 点单页自测（后端打桩，不依赖任何线上服务）
- `test-admin-static.js` — 店员后台自测（重点验"改完到底发了什么、带没带口令"）

## 店员后台怎么用

1. 打开 `admin.html`，口令就是后端那把 `AGENT_KEY`（存在服务器/`.env` 里，**不要写进这个仓库**）
2. 填后端地址 + 口令 → 「读取当前设置」→ 改店名/电话/菜单/价格/配送费规则 → 「保存到服务器」
3. 保存立刻生效：顾客刷新点单页就是新的店名、菜单和运费规则（定价只有后端一份实现）

口令只存在店员自己那台浏览器的 localStorage 里，不进网页、不随网页发出去；没有口令只能看、不能改（服务端 403）。

## 这页做不到什么

推送微信菜单、接收菜单点击回调、真出票、网页授权换 openid —— 都要后端服务器（AppID/AppSecret、公网 HTTPS 回调、加白名单的出口 IP、以及打印机）。真出票由 Worker/Python 后端接打印机完成，静态页只负责显示。
